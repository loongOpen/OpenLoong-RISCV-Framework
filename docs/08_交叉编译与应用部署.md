# 08 交叉编译与应用部署

[返回首页](../README.md) · [常见问题](09_常见问题.md)

## 两条部署路径

- **系统原生 musl 路径**：使用与 OpenHarmony 对应的 RISC-V 工具链，应用和依赖均匹配该 ABI。
- **随应用部署 glibc 路径**：使用 RISC-V glibc 工具链，应用目录内携带配套加载器与运行库，显式调用加载器，不替换系统 musl。

不要复制电脑的 x86_64 运行库，也不要混用两套 ABI 的编译产物。外部应用的编译参数按其项目文档设置。

## 最小 glibc 示例

电脑端安装 GNU RISC-V 交叉工具链后，在独立工作目录创建 `hello.c`：

```c
#include <stdio.h>
int main(void) { puts("Hello from RISC-V"); return 0; }
```

电脑端编译与检查：

```sh
mkdir -p deploy/bin deploy/lib
riscv64-linux-gnu-gcc hello.c -o deploy/bin/hello
file deploy/bin/hello
readelf -l deploy/bin/hello
readelf -d deploy/bin/hello
```

确认文件为 RISC-V ELF，并检查解释器和 NEEDED 项。常见 glibc 解释器为 `ld-linux-riscv64-lp64d.so.1`。

## 电脑端整理运行库

以下路径适用于原材料中的 Ubuntu/Debian 交叉工具链布局，实际应先检查文件存在，并确保加载器和 libc 来自同一套环境：

```sh
export GLIBC_ROOT=/usr/riscv64-linux-gnu/lib
cp -L "$GLIBC_ROOT/ld-linux-riscv64-lp64d.so.1" deploy/lib/
cp -L "$GLIBC_ROOT/libc.so.6" deploy/lib/
```

C++、数学库及其他应用还可能需要 `libstdc++.so.6`、`libgcc_s.so.1`、`libm.so.6` 等。使用交叉编译器 `-print-file-name=<库名>` 定位实际库，对程序与每个共享库执行 `readelf -d`，递归补齐 NEEDED 依赖。运行时 `dlopen` 加载的插件也需要按应用说明准备。不要在电脑直接用 `ldd` 执行未知或异架构产物。

## 电脑端传输，板端运行

电脑端：

```sh
hdc -t "$TARGET" file send deploy /data/local/tmp/hello-glibc
```

板端：

```sh
cd /data/local/tmp/hello-glibc
chmod 755 bin/hello lib/ld-linux-riscv64-lp64d.so.1
./lib/ld-linux-riscv64-lp64d.so.1 --library-path "$PWD/lib" ./bin/hello
```

预期输出 `Hello from RISC-V`。此最小例子用于验证编译、加载器和传输链路。

## 外部应用示例：loong_driver_sdk

SDK 源码、依赖和二进制本仓库不收录。操作顺序为：

1. 按所获取 SDK 版本的构建说明选择 musl 或 glibc 工具链，记录版本与编译选项。
2. 编译得到应用和共享库，整理 `bin/`、`lib/` 及该版本要求的配置文件。
3. 按上述方式核对架构、解释器和依赖，再传输到板端。
4. 先完成 CAN/USB 基础验证，再配置 SDK 使用的实际接口、波特率和设备参数。
5. 按 SDK 自身说明运行测试程序并检查结果。
