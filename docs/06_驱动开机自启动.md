# 06 驱动开机自启动

[返回首页](../README.md) · [下一步：SSH（可选）](07_SSH配置与文件传输.md)

## 前置条件

CAN、USB 六个模块已在目标板手动加载成功，并位于 `/data/apps/drivers/modules/`。本仓库脚本针对 Linux 6.18.3，加载六个模块并检查 can0 至 can5，不设置 CAN 速率，也不启动运控程序。

不同板卡需调整脚本。

## 电脑端传输

```sh
hdc -t "$TARGET" file send scripts/load-drivers.sh /data/apps/drivers/load-drivers.sh
hdc -t "$TARGET" file send configs/init.k3drivers.cfg.example /data/local/tmp/init.k3drivers.cfg
hdc -t "$TARGET" shell
```

## 板端先手动验证

```sh
chmod 755 /data/apps/drivers/load-drivers.sh
sh /data/apps/drivers/load-drivers.sh
tail -40 /data/apps/drivers/log/load-drivers.log
```

应出现 SUCCESS。脚本遇到失败即退出，已加载模块会跳过；日志包含日期和 boot_id。USB 未接入时没有 ttyUSB 节点。

## 安装启动入口

先备份现有文件，备份文件名保持唯一，不能反复覆盖初始备份：

```sh
mkdir -p /data/apps/drivers/backups
BACKUP="/data/apps/drivers/backups/init.com260.cfg.$(date +%Y%m%d-%H%M%S)"
cp /vendor/etc/init.com260.cfg "$BACKUP"
echo "$BACKUP"
mount -o remount,rw /vendor
```

若 `/vendor/etc/init.k3drivers.cfg` 已存在，先备份并检查，避免直接覆盖。首次安装时：

```sh
cp /data/local/tmp/init.k3drivers.cfg /vendor/etc/init.k3drivers.cfg
chown root:root /vendor/etc/init.k3drivers.cfg
chmod 644 /vendor/etc/init.k3drivers.cfg
vi /vendor/etc/init.com260.cfg
```

在原文件 `import` 数组追加 `"/vendor/etc/init.k3drivers.cfg"`，保留全部原有内容，已存在则不重复添加。保存后检查 JSON 语法及平台 init 配置要求，再执行：

```sh
sync
mount -o remount,ro /vendor
cat /proc/sys/kernel/random/boot_id
```

确认可用串口恢复、应用已停止且配置检查通过后，手动执行 `reboot`。
